## 元信息
- 标题：AI编程项目规则怎么迁移？Cursor Rules、CLAUDE.md、AGENTS.md 同步清单
- 日期：2026-07-20
- 分类：tools/ai编程
- 蒸馏日期：2026-07-21

## 痛点
1. 同一个项目，规则散在 Cursor Rules、CLAUDE.md、AGENTS.md 里，工具读到的要求不一样
2. 规则很长但真正有用的信息很少——大量身份设定和态度表达
3. 迁移时把所有内容复制到三个文件，后面改一处就版本不一致
4. CLAUDE.md 里临时任务和长期记忆混在一起，过期目标继续执行
5. 迁移后不验证，工具是否读到规则、是否按范围修改都不确定

## 解法
1. 规则分类：项目事实、行为约束、协作偏好、交付标准——只保留能改变工具行为的规则
2. 通用层+工具适配层：通用层放项目事实/目录/命令/安全边界，工具层只写各自读取方式和特殊限制
3. 从 CLAUDE.md 迁移时逐条标记：长期有效/阶段有效/已经过期
4. AGENTS.md 侧重执行边界：哪些命令可直接运行、修改前必须读什么、最终汇报格式
5. 建立规则对照表，记录每条规则在哪些工具里生效
6. 迁移后用低风险任务验证工具行为是否一致

## 可执行规则
1. 规则分四类：项目事实、行为约束、协作偏好、交付标准
2. 通用层+工具适配层两层分离，不复制
3. CLAUDE.md 逐条标记有效期，过期内容直接删
4. 建立规则对照表，测试命令变了知道改哪些地方
5. 迁移后用小任务验证三件事：是否读到规则、是否按范围修改、是否按要求汇报
