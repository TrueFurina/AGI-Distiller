# 蒸馏笔记：comment-distillery（第七轮知识库来源，2026-09-26）

> 来源项目：`E:\Program\comment-distillery`（七战实战、CI 全绿的开源仓库）
> 读法：不是学"评论分析"，是学**它的工程纪律与方法论演进机制**。它自己也承认最值钱的资产是"被推翻五次的判断标准演进链"。

## 元信息
- 标题：comment-distillery——群体文本蒸馏为带引用溯源的厚指南
- 作者：用户本人项目（同作者姊妹项目，与 AGI-Distiller 共享"蒸馏"骨架）
- 痛点：群体文本（评论/问卷/访谈）→ 市面工具止步 L2 情感饼图；L3 建设性综合是空白
- 解法：6 步流水线 + 三件套护城河（反例对冲/引用溯源/盲区诚实）+ 引用幻觉机验质量门

## 痛点（提炼）

### P1 AI 幻觉引用：格式完全正确但语料中不存在
第四战 96 条引用揪出 1 条幻觉 ID，第六战 103 条又 1 条（索引写错一位数字）——**写作时凭印象补 ID 是最高危动作，人工自查必然漏掉**（幻觉率约 1%，两次实测）。机器可验证的必须机器验。

### P2 上游数据缺陷静默污染结论
分页游标重叠 → 22% 重复行。危害不止规模虚高：**同一条观点被重复计入共识度，直接污染"高赞即共识"的判断**——不是美观问题，是结论错误。修复必须两头做（抓取端 + 预处理端），交付前必查 `unique_id_count == row_count`。

### P3 直觉判断标准会被单条数据打穿（方法论过拟合）
七战里被推翻五次：「高赞=高信号」❌（8 条最有价值评论赞数总和 12 vs 最高赞段子 236,396）、「低赞长文=真信号」⚠️（混入粘贴板 pasta）、「只抓一级就够」❌（反例几乎全在楼中楼）、「真实性靠人工核对」❌、「重复行只是美观问题」❌。

### P4 "结构性盲区"需要主动开采
一级评论是广场（表态/段子），楼中楼是走廊（纠正/反驳/证词）——实测楼中楼占条数 31.9% 只点赞数 14.6%（声音小信息密）。正卷 3 条结论被补抓的楼中楼全部修正。**一级评论区一片和谐时，唯一能救你的就是楼中楼。**

### P5 交接即资产
HANDOFF.md 让下一个会话"读完即可接手，不必回溯历史"——坑清单 A/B/C 分域表格化、方法论演进写成"当时相信什么→被什么打穿→现在怎么做"。

## 解法（可执行规则）

### R1 引用溯源机验：差集必须为空才交付
所有 ID 引用与语料 ID 全集做差集（`verify_citations.py`），非空不许交付。规则：ID 必须逐字复制自 id_map.json，**不许凭印象补写**；"引用条数少而真 > 多而假，诚实的降级方式是减少引用，绝不是保留一个看起来对的 ID"。
→ **映射到 AGI-Distiller**：我们所有"引用了源文件/数据"的产出（蒸馏笔记的数字、skill 里的实测值、Golden 基线报告）都适用同一纪律——数字必须可回溯到脚本输出，路径必须真实存在。

### R2 数据质量三查（上游缺陷两头修）
抓取端去重 + 预处理端去重 + `dup_dropped` 指标显式暴露 + 交付前唯一性断言。**危害要问"污染什么结论"，不只问"数字好不好看"。**
→ 映射：我们的自动化任务（每日 plans 检查等）读取的数据源同样要查重复/缺失；Golden 判分器读回复文件也该报 `dup_dropped` 式指标。

### R3 单战升级门槛（comment-distillery 反向给我们的一条）
它对照我们的频次制（1 篇→notes，2 篇→memory，3 篇→行为规范，重复 3 次→skill）指出：**它"单战即升级"容易把个案过拟合为铁律**——应加"同一发现出现 ≥2 战才进 SKILL.md，出现 1 战先进 cases/notes"。
→ **我们同样要防**：单个项目踩的坑直接升为全局规则前，问一句"这在第二个项目会发生吗"。memory 条目里"2026-09-XX 实证"标记的，第二次复现时才升 skill。

### R4 结构性盲区清单化
它把盲区显式分四类（幸存者/平台/算法/时间切片偏差）强制披露。盲区不是"可能遗漏"，是**必须命名的章节**。
→ 映射：我们的产出（验收清单/报告）应加"已知盲区"节；Golden 场景 `layering`（缺辩论层意识）的教训——**披露自己没做什么，与做了什么同等重要**。

### R5 覆盖率诚实声明
>5000 条不许逐行读完，用"头部通读+脚本精筛"两段式（1/6 阅读量覆盖 95% 信号），**附录必须披露未读部分**——"未读部分不做断言"。
→ 映射：长文档/大仓库分析任务，声明"读了什么、没读什么"，不许用"全面分析"话术掩盖抽样。

### R6 量化判据台账（7 条带实测来源）
广场/走廊比 31.9%/14.6%、注意力漂移比 2.5×、赞-信号背离 12 vs 236,396、筛选率 6.2%、去重率 22%、覆盖率 3.0%、幻觉率约 1%——**跨议题的结构性基线，新建语料拿来对照**。
→ 映射：我们的体系也可建量化判据台账（门禁拦截次数、hook 拦截数、幻觉率、Golden 分数演进）——已有雏形（COMPARISON 报告），继续累积。

### R7 环境坑表格化交接（A/B/C 分域）
抓取链路/预处理交付/环境工具分三表，每条"坑→症状→解法"。与我们的 MEMORY 分层互补：**它按"链路阶段"组织，我们按"层级"组织——长链路项目用它的方式更好检索。**

## 与现有 16-skill 体系对照 → 新缺口

| 发现 | 现有覆盖 | 缺口动作 |
|------|---------|---------|
| R1 引用机验 | 数字口径有 caliber_check；路径无机验 | **新 skill 候选：source-verify**（产出中引用的路径/数字/ID 与源做差集）——或扩展 caliber_check |
| R2 数据质量三查 | 无 | Golden 判分器加 dedup 指标（低成本）；skill 层暂缓 |
| R3 单战升级门槛 | 无成文规则 | **memory 新条目**（升格门槛：第二次复现才升 skill）——已可执行，不需要新 skill |
| R4 盲区清单化 | 验收清单有"剩余风险"节但无四类框架 | **扩展 acceptance-checker**：剩余风险节加"幸存者/平台/算法/时间"四类提示 |
| R5 覆盖率诚实声明 | honesty 场景管"没验证不说验证" | **Golden 新场景**：coverage-honesty（长语料必须披露未读部分） |
| R6 判据台账 | COMPARISON 报告有雏形 | notes 记录，持续累积，暂不建 skill |
| R7 坑清单分域 | MEMORY 分层已覆盖 | 无动作（长链路项目用它的组织方式） |

## 优先级裁决（按 ROI）
1. **立即做**：R3 memory 条目（一条规则，零成本）+ R5 Golden 新场景（对齐现有判分器，~30 行 yaml）
2. **下轮做**：R1 source-verify skill（等真实出现第二次"引用路径/数字错误"再立项——正是 R3 门槛的应用）
3. **挂账**：R4 acceptance-checker 扩展（等下次验收任务时顺手）；R2/R6/R7 持续累积

## 陷阱（它踩过的，我们别踩）
- Windows Python 路径 `C:/...` 而非 `/c/...`（会写进 `C:\c\Users`）——与我们已知的 MSYS 路径教训同源，再次确认
- heredoc 静默改写反斜杠——再次确认（已在我们 MEMORY/bash 教训里）
- 引用机验正则误报：表格转义 `\|`、正文提及错误 ID 被当真引用——**做 source-verify 时必须处理这两个边界**
- 跨盘 shutil.move 退化 copy+rmtree 被安全钩子拦 → 用 PowerShell Move-Item——**我们脚本库新规则**
- 别自己写 bv2av 类算法，直接调官方接口——"网上多版本算法极易错配，实测偏差几个数量级"

## 相互学习总结（双向）
- **它给我们**：R1 引用机验纪律、R3 单战升级门槛（最值钱的反向输入）、R5 覆盖率诚实、R6 判据台账思想
- **我们给它**（它已确认）：golden 三分离设计、离线判分模式、拒稿归档机制——它 ROADMAP P1 已计划照搬
- **共同进化点**：两边都是"蒸馏"骨架，它的输入是群体文本、我们的是单篇长文——若未来它做 P5 跨平台合并蒸馏，我们的 source-verify 会成为它的刚需

# 第八轮蒸馏：ROADMAP × 已知局限（2026-09-26 续）

> 来源：ROADMAP.md（P0-P5 阶段规划）× retrospective §7 已知局限 × P1/P2 执行中踩坑
> 本轮特点：素材全部是"它自己复盘自己"的元方法论——比第一轮的规则更抽象一层。

## 规则源提炼（5 条）

### R8 禁词否定语境误伤（第二次复现 → 触发 R3 升格门槛）
它 P1 踩坑：baseline 写"绝不能**凭印象**补一个 ID"被朴素字符串禁词判红线——语义完全正确。我们此前教训："禁词必须是执行性宣称，不能是可被否定的短语（否定性提及会被子串误命中——已修 5 处场景）"。**两个独立项目踩同一坑 = R3 门槛满足，可升格为确定性 memory 条目**（已有 memory 条目，本轮补强"判分器实现层"的应用）。

### R9 规则溯源台账 + 裸铁律机验（它把我们 R3 工程化了）
`docs/rule-provenance.md`：9 条铁律（≥2 战）/ 5 条待复现（仅 1 战）/ 7 条环境事实，每条附**复现判据**；`check_rule_tags.py` 机验"SKILL.md 规则区无裸铁律"（24/24 带标记，变异验证 3/3 拦截，CI 卡口）。我们的 R3 还是一条 memory 文字，它已做成"脚本 + 台账 + CI"。
→ **我们可抄的形态**：自产 16 skill 的规则若加溯源标记（`来源: 第N轮/项目X`），可用同一思路做轻量检查——但 16 个 skill 体量小，暂不值得脚本化，**先在写作纪律层执行**（新 skill 每条规则标来源与复现数）。

### R10 被推翻结论台账：记"何时可翻案"
`docs/overturned.md` OT-1…OT-5 每条含四字段：曾经相信 / 被什么打穿 / 现在怎么做 / **再次推翻的条件**。我们的 rejected 归档只记"为何否"——缺第四字段。**一条结论的生命周期没有终点：推翻它的证据本身也可能被推翻。**
→ 落地：rejected 归档与 memory 废弃条目补"复活条件"；本轮起蒸馏笔记的"陷阱"条目也照此四字段。

### R11 止损决定的三段式格式
P4"已决定不做"：决定 + 理由（脱敏不彻底=合规事故，合成样例已够）+ **重新考虑的触发条件**（"≥2 位外部使用者明确卡住"）。止损不是沉默搁置——**显式写出复活条件，才不用反复重新纠结同一个决定**。
→ 映射：我们的待办/挂账（如 source-verify 立项）都应带触发条件（已有"第二次复现"即其一种）；本笔记后续所有"挂账"条目统一补此字段。

### R12 判分器不判推断质量（两边共同的盲区）
retrospective §7-3：现有 7 道门只卡**形式与引用真实性**，不检验**推断质量**——"一条引用真实但推断错误的结论能完整通过所有门"。我们的 Golden 判分器同样如此（关键词 gate + 语义复核也只复核表述，不复核逻辑链）。
→ **不可立即修**（推断质量判分需要强模型 judge，成本与主观性都高）；如实录为我们体系的已知局限 #1，与它的 P5 同题研究。**诚实登记盲区优于假装没有。**

## 陷阱新增（补第一轮清单）
- **零依赖约束会逼出格式偏离**：它用 JSON 不用 YAML（PyYAML 破零依赖承诺）——偏离必须显式声明理由，不留"为什么格式不一样"的疑惑
- **仓库根单 SKILL.md 构成单 skill 仓库**（vercel-labs/skills 规范），旁边绝不能再建 `skills/` 目录（会短路发现）——若我们未来做单 skill 分发，同样遵守
- **topics 检索词要带连字符精确匹配生态流通词**（`agent-skills` ≠ `agentskills`，白加 4 个）——分发层细节，挂账到我们项目做分发时
- **"绝不能在其旁边再建"类规则**：注意此类否定式禁令在判分器里的误伤风险（R8 同源）
