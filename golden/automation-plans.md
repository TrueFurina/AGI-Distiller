# WorkBuddy 自动化任务候选方案（2026-09-23 设计）

> 配置位置：WorkBuddy 客户端 → 自动化页面 → 添加任务（AI 无法代配，需用户 UI 操作）
> 设计依据：官方"频率+动作+产出"三要素 + 例外显式写入 + 先低频试运行 + 指定输出路径
> 流水线模式：信息源 → 定时触发 → 结构化加工 → 固定位置产出

---

## 任务 1：每周蒸馏笔记汇总（WEEKLY）

| 配置项 | 值 |
|--------|-----|
| **名称** | 每周蒸馏笔记汇总 |
| **工作空间** | `C:\Users\Lenovo\.atomcode\notes`（信息源所在） |
| **定时规则** | 每周五 17:00；仅工作日语义天然满足（周五）；生效区间长期 |
| **模型** | 均衡档（汇总类任务对推理深度不敏感，省钱） |
| **推送小程序** | 开启（周五下班路上看） |

**提示词（完整可粘贴）：**

```
每周蒸馏笔记汇总任务。执行步骤：

1. 读取当前目录（~/.atomcode/notes/）下全部 .md 文件，筛选出最近 7 天内修改的文件。
2. 按主题分类：WorkBuddy/工具配置类、Golden 评估类、skill 蒸馏类、经验教训类。
3. 每类提取本周新增的可执行规则（跳过已有内容，只看增量）。
4. 生成汇总报告，包含：本周蒸馏了哪些来源、新增规则清单（每条一行）、与现有规则的重复/矛盾点、建议升格为 skill 的候选。
5. 输出 Markdown 文件保存到 C:/Users/Lenovo/.atomcode/notes/weekly-digest/ 目录，文件名格式 weekly-YYYY-MM-DD.md。
6. 报告末尾附"与上月对比"：月度规则总数变化。

例外与约束：
- 若最近 7 天无笔记更新，输出"本周无新增蒸馏内容"的一行报告即可，不生成完整文件。
- 单条规则摘要不超过 50 字，总报告不超过 1500 字。
- 不修改任何原笔记文件，只读+新建汇总文件。
```

**试运行计划**：创建后立即手动触发 1 次，确认 weekly-digest/ 目录产出正常，再挂每周五。

## 任务 2：每日 plans 检查（DAILY，轻量）

| 配置项 | 值 |
|--------|-----|
| **名称** | 每日项目 plans 健康检查 |
| **工作空间** | `E:\Program`（三个项目所在根目录） |
| **定时规则** | 每天 09:00；**例外：周六周日跳过**；生效区间长期 |
| **模型** | 快速档（检查类任务） |
| **推送小程序** | 关闭（晨间看一次即可，不推送打扰） |

**提示词（完整可粘贴）：**

```
每日项目计划外脑健康检查。执行步骤：

1. 依次检查以下三个项目的 plans/ 目录：
   - E:/Program/西湖论剑/plans/current.md
   - E:/Program/MARL/study-help-pro/plans/current.md
   - E:/Program/MARL/【CCF】区块链AI协同：面向MARL的共识机制/marl-ecdsa-consensus-chain/plans/current.md
2. 对每个项目输出三行状态：
   - "进行中"区有无未完成项（有则列出）
   - current.md 最后修改距今几天（超过 7 天未动标记"可能过期"）
   - 待办区是否为空
3. 汇总成一页日报，保存到 E:/Program/plans-daily/YYYY-MM-DD.md。
4. 只在发现以下情况时才在报告开头加 ⚠️ 标记：项目超过 14 天无任何 plans 更新、进行中事项积压超过 5 条、plans 文件丢失。

例外与约束：
- 周六周日不执行（定时规则配置跳过，prompt 层兜底判断）。
- 报告不超过 500 字。
- 只读检查，不修改任何项目文件。
```

**试运行计划**：手动触发 1 次确认三项目路径读取正常（注意【CCF】中文路径），再挂每日 9 点。

## 省钱要点（检索实测数据）
- 早报类（含搜索）：中等消耗 1 次/天；汇总类（只读本地）：较低 1 次/周
- 简单检查任务用快速/均衡档，不用深度推理档
- prompt 一次写清（条数、字数上限），减少返工轮次——自动化同样"每多一轮多一份消耗"
- 每周抽查一次执行记录，网络/登录异常会导致静默失败
