# Skill 瘦身与重构计划

## 现状问题分析

800 行的单文件 skill 存在几个典型问题：

| 问题 | 影响 |
|------|------|
| 三套部署流程全部堆在单文件 | 每次调用都加载全部内容，浪费上下文窗口 |
| 细节步骤与通用逻辑混在一起 | 难以按需加载，也不利于维护 |
| 无法针对单一云平台快速检索 | 用户只部署 AWS 时仍要读取 GCP/Azure 部分 |

## 推荐重构方案：拆分 + 按需加载

### 结构建议

```
skills/deploy-cloud/
├── skill.md              # 主入口，只做决策路由（~30 行）
├── aws-deploy.md         # AWS 专属步骤（~250 行）
├── gcp-deploy.md         # GCP 专属步骤（~250 行）
└── azure-deploy.md       # Azure 专属步骤（~250 行）
```

### 主入口文件设计思路

`skill.md` 只保留**决策逻辑**：根据用户指定的云平台，引用对应的子文件。核心是把 800 行的"全部塞进去"变成"按需读取"。

这样做的效果：
1. **上下文占用大幅下降** — 用户说"部署到 AWS"时，只加载 AWS 部分，不再读取 GCP/Azure 内容
2. **维护成本降低** — 各平台流程独立修改，互不影响
3. **可扩展** — 未来加新的云平台只需新建文件，主入口加一行引用

## 验收标准

重构后你需要验证：
1. 三种云平台的部署流程都能正常使用
2. 主入口文件保持轻量（不超过 50 行）
3. 不破坏原有 skill 的触发和调用方式
