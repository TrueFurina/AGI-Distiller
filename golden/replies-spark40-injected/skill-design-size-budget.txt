## frontmatter：精简到能触发，不承载实现细节

frontmatter 的唯一职责是**让 Agent 在技能库检索时能精准命中**，所以只放分类、触发条件、用途：

```yaml
name: skill-name          # 必须，kebab-case，全小写
description: 一句话说明，附带自然语言触发示例
```

**篇幅建议：description 控制在 2～3 句话，不要超过 3 行。** 写多了反而稀释了关键词，检索命中率下降。检索引擎靠的是 description 里的语义匹配，简洁的明确描述比冗长的全面描述效果更好。

---

## 正文：只写规则，不写废话

正文是技能的**执行指令**，读者是 Agent，不是人类散文。每一条都应该是可执行的规则或约束：

| 该写 | 不该写 |
|---|---|
| 步骤、判断条件、约束、验收标准 | 背景介绍、库文档原文、日志式叙述 |
| 引用外部模块时写清「声明什么，不写怎么实现」 | 复制粘贴的业务逻辑，占位符不清理 |

**篇幅建议：同一个 skill 尽量少跨多个步骤，内容控制在能让 Agent 完整读进去的长度。** 用编号步骤拆小，不要堆成一大段；优先跑别人说过“用这个 skill 达成了什么结果”，而不是验证“它的字数是多少”。

---

### 实操判断

- **frontmatter** 改不动了 → 正常，它本来就不该展开。
- **正文** 写长了 → 检查有没有「解释为什么」的段落，这类内容删掉，只留「要做什么、怎么做、做到什么标准」。
