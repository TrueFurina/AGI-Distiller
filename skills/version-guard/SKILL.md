# 版本管理护栏（发布/备份/回滚/灰度）

## 三类版本不混
1. **线上稳定版**：当前生产在跑，只读
2. **测试试错版**：可随便改
3. **备份回滚版**：改前快照，命名清晰

## 硬规则
- **改前必备份，备份必记录**（时间 + 改动原因 + 指向旧版本的路径）；没有回滚点的变更是赌博。
- 版本命名含四要素：场景 + 日期 + 版本号 + 状态（如 `weekly-report-20260923-v3-draft`）。
- **每次发布前写回滚预案**：一条能执行的具体命令/步骤，不是"必要时回滚"。
- 变更记录写 5 行以内：改了什么、为什么、影响面、回滚方式、验证结果——不写流水账。

## 灰度
- 多实例/多场景时先灰一个：小范围验证 → 观察 → 全量；灰度期间保留新旧双版本可切换。
