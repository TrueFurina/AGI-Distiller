# Doc Freshness — 文档与代码同步纪律

## 腐烂模式（出现即处理）
1. **Docstring 撒谎**：函数改了行为没改 docstring——比没文档更糟（误导后来者）。改函数签名/行为时，同 commit 必须改 docstring。
2. **README 数字过期**：测试数/得分/规模变了，README 还是旧值——口径检查（caliber_check）管"数字与真值对齐"，本 skill 管"改动后记得同步"。
3. **指令文件过期**：AGENTS.md/CLAUDE.md 里的命令跑不通（路径改名、依赖变更后没更新"启动命令"节）——每次改构建/目录结构，同 commit 检查指令文件的命令节。

## 陈旧内容处理规则
- **只插入「先读」横幅，不删改原文**：数字过期时原文就是历史证据，改写它 = 销毁证据。横幅写明"以下数字截至 YYYY-MM-DD，最新见 X"。
- **废弃数字有长尾**：修完主文档后，同族旧数字仍会藏在历史报告/源码包副本里——按"族"（提升率/效应量/p 值/测试数/种子数）穷举扫所有对外文件，不只修已知的坏数字。
- **交付包内的副本也要扫**：源码包/提交包里的旧报告是重灾区。

## 同步链检查（改了 A 就要想到 B）
| 改了 | 想到同步 |
|------|---------|
| 函数签名/行为 | docstring + 调用处注释 |
| 测试数量/基线 | README 测试节 + plans 里的基线数字 |
| 构建/目录结构 | AGENTS.md/CLAUDE.md 命令节 + bootstrap 模板 |
| 依赖版本 | requirements/lockfile + INSTALL 文档 |
| 发布流程 | 上线检查清单 + 发布备注模板 |

## 检查 SOP（改完代码、提交前 1 分钟）
1. `git diff --stat` 看本次改动类型 → 对照上表"想到同步"列
2. 涉及数字改动 → grep 旧值是否残留（按族穷举）
3. docstring 与新行为肉眼核对（agent 改代码时常漏）
4. 指令文件里的命令抽一条真实跑一遍（跑不通就是过期）
