# TDD with Agents — 纪律清单

## 循环纪律（每轮必守）
1. **恰一个失败测试**：一次只写一个会失败的测试（说好数量就拒绝推测性覆盖——多写的测试把实现耦合进未验证的假设）。
2. **最小实现让它绿**：只写让当前测试通过的最小代码。
3. **绿后跑全量**：每变绿一次跑完整测试套件；任何其他测试挂了 → 回退本次改动并报告"要同时满足两者需要改什么"。
4. **一步一验证**：小步可验证；禁止把一百个重构编辑堆成一个 diff——无法 review 也无法二分定位。

## 红线（agent 逃逸模式）
- **测试文件禁改**：绿色 prompt 里永远声明测试文件 off-limits；实现可疑地"恰好通过"且 diff 含测试文件改动 = 危险信号。改测试必须单独说理由。
- **不许硬编码**：实现里塞特例让测试过、套件不完整时特别危险——**读 diff**，发现硬编码立刻加下一个测试。
- **不许改公共 API**：重构不改行为，测试必须持续通过。

## 何时用 TDD，何时 vibe coding
- **用 TDD**：高风险（鉴权/支付/PII）；会被维护（半年后别人要改）；边界复杂（日期/时区/金额）；**看不出答案对错**（最关键——错了不显眼就必须有测试）。
- **vibe coding**：原型、一次性脚本、错了肉眼可见——快是正当的，别假装在跑 TDD。

## 每轮收口
- diff 里只该有：新测试 + 最小实现。多了就问"这步是最小变更吗"。
