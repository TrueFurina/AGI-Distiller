# Workspace Isolation — 多项目并行不串场

## 铁律：以「当前 workspace 的真实代码」为准
多项目并行的默认失败模式：把 A 项目的架构/文档/命令套到 B 项目——AI 读过 A 的文档后，在没有提醒时会把 A 的假设带进 B 的操作。**每条操作前，事实来源必须是当前 workspace 的文件，不是记忆里的另一个项目。**

## 操作纪律五条
1. **进场先定位**：进入项目先读该项目的 AGENTS.md / plans/current.md——这是"我在哪"的锚点，不做任何假设性操作。
2. **外来文件识别**：workspace 里出现与本项目无关的文件（如 NetLearn 的 dashboard 留在芒得很职根目录）→ 标记为"外来、勿解读为本项目模块"，建议移回，不擅自删改。
3. **路径全显式**：跨目录操作一律写完整路径（含盘符），禁止"当前目录"假设——多项目并行时 cd 错一次目录，后面全部操作落在错误 workspace。
4. **跨项目参考：只读不搬**：参考 A 项目的实现时，结论经过"适配 B 项目事实"的转换再落地——直接复制代码/配置/文档段落 = 移植隐式假设（依赖、路径、约定都不同）。
5. **同族不同项目不混淆**：名字相近的项目（MARS-408 与芒得很职共用底座但分分支；soft-skills-platform 与 MangDeHenZhi 仅名字像）——操作前确认分支名 + 远程 URL，`git remote -v` 三秒钟防推错仓。

## 串场症状自查（出现即停）
- 说了另一个项目的命令/端口/路径
- 用 A 项目的"口径"解读 B 项目的数字
- commit message 里出现别的项目的术语
- 推送前没看 remote 就 push

## 同步机制（防记忆源串场）
- 跨项目通用规则 → USER.md（唯一入口），项目专属 → 各自 MEMORY.md/plans——**项目事实只写一处**，写两处必漂移
- 会话开始若发现自己在读"记忆里的另一个项目"的细节 → 停下，重新读当前项目的 AGENTS.md 对齐锚点
