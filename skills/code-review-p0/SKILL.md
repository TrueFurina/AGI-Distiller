# P0/P1/P2 分级代码审查

用户请求: $ARGUMENTS

## 规则

1. 按 P0/P1/P2 三级输出，不允许只给结论不给证据。
2. 每条问题必须包含：文件位置、原因、影响、建议动作。
3. **没有证据的问题不写**——不猜、不脑补、不把"可能"当"确定"。
4. 重点看：删除行、条件判断、默认值、配置文件、权限校验、SQL 拼接、循环查库。
5. 审查的是代码 diff，不是听 AI 的总结。

---

## 分级标准

| 级别 | 定义 | 典型场景 |
|------|------|----------|
| **P0** | 会导致线上错误、数据损坏或安全风险 | SQL 注入、越权、资损、死循环、删除线上数据、密钥泄露 |
| **P1** | 会影响功能、测试或可维护性的明显问题 | N+1 查询、缺参数校验、缺空值处理、测试缺失、命名混乱 |
| **P2** | 可选优化 | 代码重复、注释缺失、可简化逻辑、性能微调 |

---

## 审查维度

1. **正确性**：逻辑是否符合预期，边界条件是否覆盖
2. **安全性**：SQL 注入、XSS、权限校验、敏感信息
3. **性能**：N+1、循环查库、无索引查询、缓存
4. **可维护性**：命名、复杂度、重复代码、注释、结构
5. **测试**：是否有测试覆盖关键路径

---

## 执行步骤

### 步骤 1：获取改动范围

```bash
git diff --stat 2>/dev/null
echo "---"
git diff 2>/dev/null | head -200
```

### 步骤 2：重点扫描高危模式

```bash
# 删除行
git diff 2>/dev/null | grep "^-" | grep -v "^---" | head -30
# 新增条件判断
git diff 2>/dev/null | grep "^+.*if\|^+.*switch\|^+.*else\|^+.*match" | head -20
# SQL 拼接 / 循环查库 / 硬编码密钥
git diff 2>/dev/null | grep -iE "select \*|for.*query|password|secret|api_key|token" | head -20
# 配置文件
git diff --name-only 2>/dev/null | grep -iE "config|\.env|\.yml|\.json|\.toml"
```

### 步骤 3：分级输出

按 P0 → P1 → P2 顺序，每条给出证据。

---

## 输出格式

```
# 代码审查报告

## P0（必须修复，阻塞合并）
- [文件:行号] 问题描述
  - 原因：...
  - 影响：...
  - 建议：...

## P1（应该修复）
- [文件:行号] 问题描述
  - 原因：...
  - 影响：...
  - 建议：...

## P2（可选优化）
- [文件:行号] 问题描述
  - 建议：...

## 审查结论
✅ 可合并 / ⚠️ 修复 P0 后可合并 / ❌ 需重做

## 未验证项（如实标注）
- 未跑的测试：...
- 不确定的风险：...
```
